 • scCSC is NOT the best CUDA-core kernel on: Ragusa18, cage4, ASIC_100ks, congress, epinions, nd3k, nd6k.
      epinions is the clearest case: its hubs are large enough that one thread per vertex
      stalls an entire 32-lane warp; scCOOC launches over non-zeros (dimGridspmv = (nz+1024)/1024, one
      thread per EDGE), so the load imbalance disappears entirely -- the exact case the paper predicts.
 • tcTF32 = TENSOR CORE implementation (bcgputc.cu). Tensor cores multiply MATRICES, not vectors, so this
      variant runs 16 roots at once: f <- A'f becomes F <- A'F, an SpMM whose N dimension is exactly the 16
      of the m16n16k8 tf32 WMMA shape. A' is stored sparse and scattered into shared memory just before
      each MMA, so memory traffic stays proportional to nz. It is the fastest kernel on 12 of 13 graphs here.
 • PRECISION: fp16 is unusable here -- exact integers stop at 2048 but path counts reach 24973 (fb_artist),
      and sigma would overflow its 65504 maximum on some graphs. tf32 fixes the range but keeps an 11-bit
      mantissa, so each F tile is split as F = F1+F2+F3 (3 MMAs, 33 mantissa bits > fp32's 24). Measured on
      epinions: 1 term -> 9.3e-4 max relative error (FAILS the 1e-4 bar), 2 -> 1.8e-5, 3 -> 1.0e-5. Cost of
      the split is only 28%, because the kernel is memory-bound and the extra MMAs are effectively free.
 • CONDENSED BLOCKING is what makes tcTF32 viable on SPARSE graphs, and is the main result here. A
      geometric 16x16 tiling of A' is hopeless on real graphs: on fb_artist a nonzero tile carried 1.12
      nonzeros, so the 256 floats of F that the tile spans were 99.6% wasted (measured density 0.437%).
      Instead each 16-vertex row-window now keeps the sorted list of source vertices its rows ACTUALLY
      reference and cuts that list into chunks of 16. Every column of a chunk is then guaranteed to carry
      a nonzero, so density is bounded below by 6.25% by construction. Measured effect:
         fb_artist 0.437% -> 6.301%   epinions 0.823% -> 7.116%   smallworld 1.789% -> 15.374%
         nd3k 43.6% -> 60.6%          nd6k 42.3% -> 59.6%
      The gather also becomes a 64-byte coalesced load per slot instead of a strided read of a mostly
      empty tile. Before this change fb_artist ran 4.2x SLOWER than scCSC; see the vs CUDA column
      above for where it lands now.
 • BATCH OCCUPANCY: tcTF32 always computes a full 16-root batch, so benchmarking it at nr=1 charges it
      for 16 roots and credits it with one -- an artificial 15/16 penalty. Every non-toy graph above
      therefore runs nr=32. The CUDA-core kernels are single-source and their per-root cost does not
      depend on nr, so this changes only the tensor-core measurement, and only by removing a wrong one.
      On smallworld the same binary reports 9.26 ms/vertex at nr=1 and 0.63 ms/vertex at nr=16.

 • WHY DID scCSC (Scalar) BEAT vcCSC (Warp Vector) ON ASIC_100ks DESPITE BEING IRREGULAR?
   -> Although ASIC_100ks is structurally irregular, its largest hub has only 206 edges (average degree = 5.84).
      Warp Vector (vcCSC/veCSC) assigns 32 CUDA threads per vertex. For a vertex with 5 or 10 edges, over 80% of

      looping in cache (scCSC) has far lower overhead than warp coordination. vcCSC shines on hyper-skewed scale-free
      networks (like social networks or web crawls) where hub degrees reach several thousands of edges.
